How it works

From URL to fix list in four steps.

  1. 01

    Connect

    Add your site. Add login steps so private pages and dashboards are tested too.

  2. 02

    Scan

    Every page is crawled and tested in a real browser on each device profile.

  3. 03

    Review

    Open the report. Issues are ranked, located on screenshots and explained.

  4. 04

    Automate

    Trigger scans from CI and block a release when critical issues appear.

deploy.yml
# Block the release when critical issues are found
- name: Proofline scan
  run: |
    ID=$(curl -s -X POST $PROOFLINE_URL/api/v1/scans \
      -H "Authorization: Bearer $PROOFLINE_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"url": "https://staging.example.com"}' | jq -r .id)
    # poll until the scan is done, then
    test "$(curl -s $PROOFLINE_URL/api/v1/scans/$ID \
      -H "Authorization: Bearer $PROOFLINE_TOKEN" \
      | jq .summary.bySeverity.critical)" = "0"

FAQ

Questions, answered.

Something else? Talk to our team.

Does it work with our stack?

Yes, if your product runs in a browser. Proofline tests the rendered application the way your users see it, so the framework and backend language do not matter.

Can it test pages behind a login?

Yes. Add login steps once and every scan signs in first. Use a dedicated test account; its password is stored securely and never shown again.

Do we need to write code?

No. A scan only needs a URL. User flows are written as simple steps such as click, fill and expect text.

How is this different from a single audit tool?

Proofline crawls every page on four device sizes and combines functional flows, accessibility, layout, performance, links and visual changes in one prioritised report.
